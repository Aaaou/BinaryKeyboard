# CH592F 2.4G 配码与接收器设计

> 状态：协议、Studio 接口和键盘 FN 动作已预留；当前仓库的普通 CH592F 键盘构建没有链接 RF FAST 后端，也没有可刷的 CH592F 接收器工程。因此本页的配码流程适用于后续 `RF-enabled` 键盘和接收器固件，不能把当前 BLE 固件当作 2.4G 固件使用。

## 运行模式与轮询率

正常的模式切换顺序是 `USB -> BLE -> 2.4G -> USB`，但只有键盘实际报告 2.4G 能力时，才将 2.4G 放入 FN 的“切换模式”循环。普通 BLE 固件保持原来的 `USB <-> BLE`，不会误切到空模式。

接收器使用 USB Full-Speed HID，支持 `125 / 250 / 500 / 1000 Hz`，默认 `1000 Hz`。设置入口是 Studio 的“2.4G 无线与接收器”。修改轮询率由接收器保存；接收器可在下一次 USB 重新枚举后应用新间隔。CH592F USB Full-Speed 的主机侧上限约为 1000 Hz，不提供表面上没有实际收益的 2K/4K/8K 选项。

## 灯光状态

以下使用第一颗状态灯；最终接收器固件需要复用键盘当前 RGB 指示 API：

| 状态 | 灯光 |
| --- | --- |
| 接收器无绑定，自动等待配码 | 蓝色双闪，约每秒一次，持续 60 秒 |
| Studio 或 FN 手动开始配码 | 紫色快闪，持续 60 秒 |
| 配码成功 | 绿色常亮约 500 ms，随后进入连接状态 |
| 配码超时或验证失败 | 红色闪 3 次 |
| 双端解绑成功 | 黄色闪 2 次 |
| 2.4G 已连接 | 沿用无线连接指示；不长期占用 RGB 灯效 |

## 首次配对

1. 首次给接收器烧录接收器固件后插入电脑。接收器没有有效绑定记录，会自动进入 60 秒蓝色双闪窗口。
2. 用 USB 或 BLE 连接 Studio，打开键盘的“2.4G 无线与接收器”，点击“开始配码”。键盘紫色快闪。
3. 在 60 秒内，接收器和键盘交换一次临时会话、设备标识和绑定摘要。两端只有在收到提交确认后才把记录写入 Flash。
4. 成功时两端绿灯短亮，Studio 显示“已绑定”或“已连接”。此后接收器只寻找已绑定键盘，不接受附近的陌生键盘。

键盘默认没有配码 FN 绑定。RF-enabled 固件连接 Studio 后，才会在 FN 的“长按”下拉项中出现“进入 2.4G 配码”；建议把它放在长按，不要放在普通点击。日常配码不依赖 BOOT 引脚，PB22 改接 PB11 仅保留给恢复刷写。

## 清除与重新配码

不要把“清除键盘绑定”和“清除接收器绑定”设计成互不知情的两个普通按钮。正确的默认操作是 Studio 的“重新配码”：

1. Studio 对当前一端发出解绑请求。
2. 该端经 2.4G 通知已绑定的另一端；另一端清除本地记录并回确认。
3. 两端收到确认后再提交本地清除，随后接收器自动开启 60 秒配码窗口。

接收器和键盘都应保留一个“清除绑定”入口，但默认使用上面的双端事务。若另一端离线，Studio 必须提示“远端未确认”，而不是悄悄声称已完成双端解绑。用户可以二次确认“强制清除本端”：

- 强制清除接收器后，接收器不是废设备。它进入无绑定状态并自动开启配码窗口；原键盘仍保存旧记录，但会因找不到接收器而进入“绑定失效”，可在键盘端清除或直接重新配码。
- 强制清除键盘后，接收器也不是废设备。它仍保存旧绑定并只会寻找旧键盘；可连接 Studio 后在接收器页点击“清除并重新配码”，或等待旧键盘重新加入完成事务。

因此，常规换键盘、换接收器、转售前的建议操作一律是“重新配码”，而不是分别点击两端的强制清除。

## Studio 与 HID 协议

Studio 通过 HID Vendor 接口发现设备及其 collection；它不读取或展示原始 HID report descriptor 作为配置协议。设备信息、角色、配码状态、轮询率和配码控制都走有版本的 Vendor HID 命令：

```text
RADIO_CAPS           当前角色、是否启用 RF、支持的轮询率
RADIO_PAIR_STATUS    unbound / pairing / bound / connected / inconsistent
RADIO_PAIR_START     开启 60 秒配码窗口
RADIO_PAIR_CANCEL    取消本次窗口
RADIO_PAIR_CLEAR     发起双端解绑事务
RADIO_POLL_RATE_GET  读取接收器 USB 轮询率
RADIO_POLL_RATE_SET  设置 125/250/500/1000 Hz
```

绑定数据只向 Studio 返回角色、状态、会话编号和非敏感设备标识。不要通过网页读取或导出配码密钥。

## 实现边界

本分支没有提供假接收器镜像。实现真正可刷的 CH592F 接收器前，还必须单独完成并实测：RF FAST Host/Device 初始化、加密/去重、重发、接收器 USB HID 报告、双端 Flash 事务和丢包/断电恢复。协议与 UI 的意义是让这项工作有稳定接口，并保证旧固件不会误开启 2.4G 功能。
