## 问题修复

- 修复 USB `SUSPENDED` 状态被 `>= USB_STATE_CONFIGURED` 错误判定为有效 USB，导致未连接 USB 时仍被阻止休眠。现在只接受严格的 `USB_STATE_CONFIGURED`。
- 修复无有效 DataFlash 配置时只在 RAM 中使用默认值的问题。首次启动会保存默认配置，已有用户配置不会被覆盖。
- 修复 LIGHT、DEEP 和 FN 长按阈值未完整使用设备实际配置的问题。
- 修复 FN 长按休眠后，松开同一个 FN 会立即把设备唤醒的问题。
- FN 仍处于按下状态时延后进入 DEEP，避免深睡唤醒源在进入瞬间已有效。
- 修复 `build-full --build-number` 只更新产物文件名、却可能沿用缓存版本头的问题；现在文件名和设备上报版本会同步为同一个版本。
- 修复 issue #75：KNOB 的 K1/K2、K3/K4 RGB 物理顺序对调。统一在板级逻辑到物理 LED 映射中修正，静态、彩虹、按键响应和层提示使用同一套顺序；5KEY 不受影响。
- 修复 BLE 在 LIGHT 入口后断开：不再由应用层直接执行 CPU Idle，而是在 LIGHT 期间启用 WCH BLE 调度器的低功耗回调，按连接事件安全睡眠；ACTIVE 期间保持禁用，避免打断 RGB TMR1/DMA。
- BLE 模式不再安装独立的 DEEP RTC 定时器，而是在每次连接事件唤醒后按总空闲时间判断；避免 `DEEP=0` 的取消逻辑关闭 BLE 共用的 RTC 唤醒源并导致监督超时断线。
- LIGHT 的 GPIO 唤醒现在只接受真实键位或旋钮的有效边沿，并校验引脚当前电平；端口残留标志和无关 GPIO 中断不会再退出 LIGHT、重置空闲计时。
- BLE 模式虽然保留 USB Device 供 Studio 插线配置，但未完成 USB 枚举时的伪传输、总线复位和悬空标志不再请求退出 LIGHT；只有真正 `CONFIGURED` 的 USB 主机可以唤醒。
- DEEP 唤醒不再依赖容易被 SDK 后续软件复位覆盖的复位状态枚举。进入 Shutdown 前写入复位保持标记，启动时在外设初始化清标志前保存 GPIO 唤醒源。
- 修复快速短按在 10 ms 锁定窗口内完成时，真实 RELEASE 被清除而导致主机持续连发的问题；消抖解锁时现在重新采样物理电平并补齐错过的边沿。
- 普通键队列满时优先保留 RELEASE；BLE 暂时无资源时保留最新完整键盘状态，并在成功发送前停止消费下一条键盘边沿。
- DEEP 不再回放唤醒键或重连期间输入；唤醒后按标准无线重连流程恢复输入。
- 2.4G 休眠计时修复同时适用于单独 2.4G 固件和三模固件的 2.4G 模式：两者均使用 RF FAST 侧可靠的毫秒计时基准，不再依赖不适用的 RF RTC 计数，因此可正常进入 LIGHT/DEEP。
- 2.4G LIGHT 灯光路径与三模 2.4G 模式统一：进入 LIGHT 前停止 RGB 调度并关闭 LED 电源，唤醒后恢复调度和状态指示，避免灯效任务或 RF 状态回调阻止休眠、造成灯光残留。
- 修复三模 FN 模式切换回到 2.4G 的问题：模式切换同时写入并校验三模启动选择器，三模引导器优先读取该选择器，再按 `USB -> BLE -> 2.4G` 选择固定镜像；避免 2.4G 复位后因只读取 runtime 页而反复启动 2.4G。

## 行为变化

- FN 长按达到每个 FN 独立配置的阈值后立即执行，不再等待松开；一次长按只触发一次。
- `DEEP` 时间定义为进入 LIGHT 后的追加等待时间，不是从最后一次操作开始重新计算的绝对时间。
- 增加“LIGHT 无感唤醒”开关，默认开启。关闭后，LIGHT 唤醒首键只负责唤醒；BLE 和 2.4G DEEP 首键只负责启动，重连期间输入不回放。
- VBAT 分压改为按需供电：采样前打开 PA15，采样完成后关闭 PA15；ADC 模拟域保持开启，方便维修时判断主控运行状态。

## 唤醒与输入同步规则

- LIGHT：唤醒键的真实 PRESS/RELEASE 继续进入正常按键链路，每个真实物理 PRESS 最多执行一次。
- 连续按三次：扫描恢复后捕获到三组真实边沿就输出三次，不合成次数，也不只保留最后一次。
- 按住唤醒：发送一次 PRESS，真实松开时发送 RELEASE；字符连发由操作系统处理。
- DEEP：主控会复位并重新连接当前无线传输。BLE 的唤醒键和重连期间输入全部丢弃；2.4G 开启独立 DEEP 无感开关时只保留一个普通唤醒键。
- DEEP 恢复后先发送全零键盘报告；如果 BLE 暂时无资源就继续重试，成功后才开放新输入。
- 连接尚未达到安全 HID 状态时，普通键和旋钮事件会直接丢弃，不会在稍后补发；FN 事件属于本地控制，仍会立即处理。
- 修复未插 USB 时切换到 USB 模式后 FN1/FN2 失灵的问题。`KBD_Core_Process()` 不再用 HID 传输就绪状态屏蔽 FN 队列，因此可以在离线 USB 模式下切回 BLE / 2.4G 或切换层；普通输入仍不会被缓存或误发。

### 离线 USB 模式回归测试

1. 断开 USB，使用 FN1 切换到 USB 模式并等待设备重启。
2. 保持 USB 断开，再按 FN1，设备应能切回 BLE（或按三模循环进入下一无线模式）。
3. 按 FN2 短按确认当前层可以切换；普通键在 USB 未枚举时不应向主机发送报告。
4. 插回 USB 后确认不会补发断开期间的普通按键或旋钮事件。

## 测试模式

- 正式固件不包含睡眠诊断周期闪灯；休眠状态以实际灯光关闭和唤醒行为判断。

## 配置与协议兼容

- DataFlash 配置结构保持 64 字节，不提升布局版本，不清空旧键位、FN、RGB 或休眠设置。
- “LIGHT 无感唤醒”使用系统配置保留区的一个字节和显式标记值；旧槽位中的其他值按默认开启迁移。
- RGB/电源读取响应保持标准 12/13 字节兼容格式，不再包含 2.4G DEEP 无感回放字段。

## 2026-09-04 三模 FN 切换回归

- 现象：KNOB 三模连接 2.4G 后，FN2 配置为“模式切换”时反复重连 2.4G，无法进入 USB/BLE。
- 日志结论：RF Host、配码、有效帧和 USB 提交均正常，故障发生在键盘复位后的镜像选择，不是 RF 链路或接收器问题。
- 根因：休眠整理后的版本漏掉三模启动选择器的写入/校验和引导器读取，runtime 模式保存不足以保证启动分区选择。
- 修复：恢复 `0x5F00` 三模选择器；FN 切换时持久化目标模式；引导器优先读取并校验选择器，失效时回退到 runtime 页。
- 验证：KNOB 三模完整 HEX 重新生成，`0x01000` 2.4G、`0x11000` BLE、`0x6D000` IAP 分区均存在；提交 `e14fc0c` 已推送 `fork/feat/ch592-2g4-macro-management`。

## 2026-08-25 低功耗入口校验

- DEEP 入口在关闭 USB Device、移除 D+ 上拉、关闭 USB/RTC/电池唤醒源并清除
  pending IRQ 后再执行 `LowPower_Shutdown(0)`，避免 BLE 模式保留的 Vendor HID
  外设或残留中断把芯片立即拉回运行态。
- 启动最早阶段恢复 WCH 低功耗示例的全 GPIO 上拉；按键、USB、ADC、RGB 和旋钮
  初始化随后覆盖各自引脚，未使用 GPIO 不再浮空。
- 休眠判定没有回退：USB 仅在严格 `USB_STATE_CONFIGURED` 时阻止自动休眠，
  `auto_sleep_min=0` 仍禁用 LIGHT，`deep_sleep_min=0` 仍禁用 DEEP。
- 实机冷启动后测得 DEEP 静态电流约 **4.7 µA**。烧录器“烧录完成后直接运行”
  可能保留 USB/复位瞬态；功耗测试应在重新复位或断电上电后进行，不能把该瞬态
  误判为固件不进休眠。
