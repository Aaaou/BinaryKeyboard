## 本轮已完成

1. **USB 管理命令长度校验**
   - 只接受完整的 64 字节 HID 管理报告。
   - 命令内 `len` 超过 61 字节时返回 `KBD_RESP_ERR_PARAM`。
   - 修复了原先可能从 `data[61]` 之外读取数据的越界风险。

2. **USB 命令移出中断上下文**
   - USB IRQ 只复制命令到有限 RX 队列。
   - Flash、配码、状态读取和响应构造在接收器主循环执行。
   - EP4 响应进入 TX 队列，不再在 IRQ 中等待 endpoint；USB reset 会清空管理
     RX/TX 队列，避免旧连接的命令或响应污染新枚举。

3. **接收器固定 ISP 完整包**
   - 接收器不再链接 `kbd_iap.c`，`0x80-0x84` 统一返回无效命令。
   - 接收器专用 JumpIAP 直接跳转 `0x01000`，不依赖 `0x6D000` 高地址 IAP。
   - 发布脚本只为接收器生成并展示 `CH592F-RECEIVER-full.hex` 和
     `CH592F-RECEIVER-full.bin`；网页 capability 的 `iap` 为 `false`。
   - 文件名保持既有约定，不引入 `dev-*` 或版本后缀。

## 第 4 项：USB reset 清队列的作用和风险

USB reset 是电脑重新枚举设备时的总线事件。若旧管理队列不清空，重新插拔后
可能把上一次连接残留的命令或响应发给新连接，表现为网页超时、响应错配或
“刚连接就收到旧状态”。现在清的是管理 RX/TX 队列，属于低风险、可恢复的
一致性保护；它不会擦除 RF 配对 DataFlash，也不会改变绑定信息。

RF/HID 报告队列属于运行数据，不是管理事务。本个人作品版本不把极端 USB reset
与 RF 同时发生的边界扩展成发布阻断项；正常拔插回归仍需确认没有残留按键。

## 明确不再继续的事项

- **约 5 秒断联释放：** 已尝试 KEEPALIVE、应用层看门狗、Timer 强制释放和主动
  RF 重启；它们会误判、填满 RF TX 描述符或破坏 RFBound 自恢复。当前按 WCH
  RFBound 官方语义运行，断电前未收到松开报告时，释放延迟属于芯片底层限制，
  官方参考同样无法保证快速终止。该现象记录为已知限制，不再反复修改。
- **极端掉电/抢占场景：** 个人作品不纳入完整故障注入和安全认证要求。
- **轮询率性能测试：** 浏览器端当前会卡死且读回值为 30，测试结果无效；保留
  配置命令和常规选项，不以该测试作为接收器发布门槛。

## 发布前仍需做的硬件确认

只需在接收器拆线前完成一次：ROM Boot 入口、完整包 ISP 烧录、USB 枚举、RF Host
启动、配码、HID 输入、拔插恢复和配对记录保留。拆线后接收器不再刷写；后续只
修改键盘固件和网页。若未来出现新硬件或必须修复接收器，必须恢复 BOOT 入口并
重新走同一套全量验收。
